# Direct requirement facets

[Русский](../ru/requirement-facets.md)

The [completion map](../product-status.json) keeps direct requirement-to-check associations as well as the acceptance-scenario links. A passing test establishes its own assertions; the union of every test linked to a scenario does not automatically prove each requirement in that scenario.

This documentation change adds 11 direct associations to existing checks for three requirements. It retains all previous associations, 53 requirements, 35 acceptance scenarios and 628 unique check identities. It changes no Go code, test behavior, formats or acceptance states.

All named checks already existed. Their source identity, conditional environment and actual execution record must still be checked at acceptance. Adding a link creates no new runtime evidence. Full source/peer/cloud/asymmetric scale, installation, current OTLP interoperability and the real owner profile retain their separate gates.

REQ-47's repository-governance checks remain in the authoritative catalog's `documentChecks`: `scripts/check-docs.mjs` and `scripts/check-standard-adoption.mjs`. An empty Go-check list for that documentary facet is intentional. Documentation coherence and rejection controls do not certify the associated product profiles.
