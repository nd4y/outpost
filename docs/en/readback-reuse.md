# Reusing immutable-object readback

[Русский](../ru/readback-reuse.md)

Cloud audits also retain [bounded SHA-256 prefix progress](verification-windows.md#cloud-object-prefixes) after each actual multipart read. A resumed prefix retains its original age and never claims a fresh full read.

Peer and external-storage clients implement this contract through separate explicit owner policies with a maximum evidence age. Both default to disabled. They change verification cost, not placement, writer trust, object identity, retention or deletion authority.

A successful independent read of an immutable object may be retained in private local state, bound to the protocol, exact endpoint, target identity/profile, reader and generation trust. The record includes object digest, length and the original successful-read time. Reuse requires every binding and the age limit to match. Missing or expired evidence requires a fresh content read. Malformed evidence fails closed. Losing a cache causes additional reads, never loss of recovery data. Cache eviction removes only advisory evidence.

An operation always reads and validates its selected signed catalog. New objects are independently read and hashed after transfer. The receiving peer still verifies its complete local closure before publication. With reuse, the sender reports a distinct cached-readback level and the oldest supporting read time; a new target claim cannot refresh that time. An old observation is not proof that an untrusted target still holds the object. Scheduled fresh verification and restore exercises remain necessary to detect subsequent loss or corruption.

Set `peerReadbackMaxAgeSeconds` in the owner-signed domain configuration to enable reuse for outgoing peer pushes, between 1 and 31622400 seconds. Zero selects fresh-only reads and bypasses the cache. A reused receipt has format `outpost-peer-readback-2`, level `client-cached-readback` and the oldest supporting object-read time. `cachedObjects` is reported separately from transferred and readback payload bytes. The target's full-read claim remains separate.

The private cache has 256 digest-prefix pages per scope, at most 4096 records and 1 MiB per page, under the same disk admission as the peer journal. A full page evicts its oldest advisory records; it never deletes payload or releases pins. Writes are atomic and network reads run outside the state lock. A successful batch of at most 16 objects is persisted before the next batch. Missing cache pages cause fresh reads; malformed pages block enabled reuse and are preserved. The oldest evidence must still satisfy the policy when the audit finishes.

Fresh-only operation remains available for audits. Old binaries reject journals containing the new receipt format; do not claim binary rollback without a compatible journal reader. Immutable backup formats and independent recovery remain unchanged. Upgrade the affected readers before enabling the optional configuration field. Unknown formats must never trigger journal reinitialization.

For S3-compatible and WebDAV targets, `cloudReadbackMaxAgeSeconds` sets the same bounded age policy independently of peer pushes. The worker shares its quota-admitted private cache between upload operations. Evidence binds the full target profile, reader and generation trust, and uses the hash of the exact canonical blob descriptor plus logical length. This also binds every multipart digest and size. Each attempt checks the actual remote descriptor before reusing payload evidence; an object ID alone cannot authorize an altered map. An absent descriptor invalidates previous evidence and requires real part reads before resealing. Detected loss, corruption or a conflicting map invalidates the affected evidence with a bounded local write even when the network attempt is cancelled.

Cloud verification persists each successfully read logical object, so another attempt can continue the audit. Reused objects avoid repeated part reads and uploads, but catalog and descriptor reads still occur. Publication checks the complete signed dependency set under this policy and writes `COMPLETE` last. Receipts distinguish `cached-target-readback` from `full-target-readback` and retain the oldest supporting payload-read time. Enabling reuse requires upgraded queue/journal readers. A cached receipt is historical evidence, not a current persistence guarantee from an untrusted target. Ordinary storage publication and every recovery read continue to hash actual bytes; the recovery path never consumes this cache. A new audit operation with the age policy set to zero requires fresh reads.

Acceptance compares initial transfer, an unchanged retry and a changed generation using actual test-endpoint request/response payload counts. It checks retained original age, expiry, corruption, restart and isolation between target scopes. Payload counters exclude TLS/HTTP overhead and cannot be reported as total wire bytes. Full local closure scans, large-generation deadline/throughput measurements, cache metadata costs, scheduled fresh verification and the 100 GiB traffic target remain separate acceptance work.

Known cloud-object loss also advances a private evidence epoch shared by concurrent operations for the exact descriptor/target/reader/trust. Cache keys include that epoch. The epoch is durable before old-record removal, so a crash cannot make a retained old record current again. Final evidence writes recheck the epoch under the shared lock; a stale operation retries with a new audit. Epoch files are quota-admitted, preserved on corruption and never automatically removed. This private verification state requires compatible readers; an older binary that ignores it is not a supported rollback while reuse is enabled.
