# Проверка ТЗ по стандарту разработки

[English](../en/standard-review.md)

Дата проверки: 6 ноября 2026 года. ТЗ 1.4, стандарт 0.4.0, закреплённая ревизия источника 75833a42311832d1de665d0e441adac2b5b701d2.

Для всех 45 правил зафиксировано требование или правило репозитория. PASS в таблице означает покрытие проектом в этой версии. Проверка продукта по каждому правилу остаётся NOT_VERIFIED: производственный движок, полная приёмка и выпуск здесь не реализованы; синтетическая фикстура G1 является отдельным частичным результатом. Выполнение проверок репозитория и защиту хостинга подтверждают результаты Actions для точного commit и настройки, отдельно от авторского ревью.

Проверка выявила отсутствие явных этапов и трассировки требований, компактного паспорта, приёмки доступности, полной проверки входных границ, условий совместимости/миграции, выпуска артефактов и сквозной проверки уведомлений. Пробелы ТЗ закрыты REQ-47-REQ-53 и AT-31-AT-35. Пределы и SLO остаются измерениями M0 и каждого выпуска. Размещение теперь задаётся доверенными нодами, недоверенными нодами и внешними хранилищами без частных примеров хостов и коллекций.

Версия 1.2 добавляет допуск по монтированию/идентичности, действующие ресурсные профили, полный расчёт ёмкости, покрытие восстановления источника и прямые связи с авариями/квотами. Частные характеристики хостов остаются вне Git. Это покрытие требований; runtime и холодный запуск на площадках остаются NOT_VERIFIED.

Версия 1.3 задаёт внешние хранилища через S3-совместимые API и WebDAV, убирает маршруты и архивные классы конкретных поставщиков, сохраняет приёмку возможностей и области credentials каждого endpoint. Связи REQ-28/30/40 и AT-16 сохранены; это не означает, что все endpoint проверены.

Версия 1.4 фиксирует выбор формата G1 в REQ-01/46 и AT-24: готовые реализации разбиения и криптографии с автономным читателем Outpost при сохранении восстановления полной реплики без сети. Сравнительные данные restic сохраняют нативный читатель. [Доказательства G1](g1-acceptance.md) отдельно связывают проверки реализации и численные затраты; G2/G3, полная продуктовая приёмка и миграции остаются непроверенными. Ни один ID требования или сценарий приёмки не удалён.
