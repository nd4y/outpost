# Интерфейс управления

[English](../en/management-ui.md)

Сервис управления отдаёт встроенный интерфейс по `/`, ресурсы - по `/ui/app.js`, `/ui/journal.js` и `/ui/app.css`. Это точные GET-маршруты с аутентификацией на настроенном адресе сервиса. Интерфейс и API используют один клиентский сертификат и локальные назначения ролей и областей доступа. Внешних скриптов, шрифтов, аналитики, прокси содержимого копий и ключей расшифрования нет. Окончательное решение о доступе принимает API.

Выберите зарегистрированную ноду и домен, чтобы посмотреть источники, размещение, маршруты, внешние хранилища, подписанные отчёты, поколения, очереди и место. Исходное время наблюдения остаётся видимым. Отсутствующее значение означает неизвестность, а не ноль. Завершённая передача не доказывает проверку целевого хранилища или доверенное восстановление. После сбоя обновите данные; смена области очищает предыдущее представление.

Владелец выбирает уже подписанный файл конфигурации, проверяет точный хеш и изменения, затем применяет просмотренный вариант к наблюдаемой ревизии. Браузер не подписывает политику. Оператор выбирает доступную команду и точный объект. Для восстановления обязательно указать поколение и локально разрешённый профиль; необязательные идентификаторы версий файлов берутся из приватного каталога восстановления. Пустой список версий означает восстановление всего выбранного поколения. Для обслуживания нужен отдельно подписанный допуск.

Каждое изменение получает идентификатор операции до отправки. Локальный журнал браузера разделён по пользователям и хранит до 16 операций и 3 МиБ после закрытия вкладок и перезапуска браузера. Web Locks согласует запись журнала и ограничивает ожидание отправки от одного пользователя 15 секундами. Одновременные одинаковые черновики используют сохранённые байты запроса и идентификатор; независимые записи не заменяют чужие квитанции. Для новой работы нужны доступные local storage и Web Locks. Согласование действует внутри одного профиля браузера и адреса сервиса, а не между независимыми устройствами.

Записи старого session storage переносятся только после сохранения и повторного чтения объединённого журнала. Отсутствие Web Locks, повреждение или заполнение хранилища и незавершённый перенос блокируют отправку. Неподтверждённые записи нельзя удалить; завершённую квитанцию можно убрать локально, сохранив удалённую операцию. Старая вкладка не может восстановить удалённую запись. После освобождения места черновик нужно проверить заново.

После потери ответа перечитайте квитанцию; повтор применения конфигурации требует того же подписанного файла. Перед отправкой проверяются текущие роли и области сессии, а сохранённый просмотр конфигурации требует разрешённого чтения квитанции или нового просмотра на сервере. При смене прав старое представление очищается. Исходные подписанные полномочия и допуски остаются в журнале браузера, поэтому используйте приватный профиль на подконтрольном устройстве. Данные браузера могут быть очищены или вытеснены и не заменяют долговечный аудит. Сохраняйте идентификаторы операций отдельно; аудит и API квитанций сервиса остаются способом восстановления. Локальное удаление и очистка браузера не отменяют удалённую работу.

Русская и английская версии используют нативные элементы, явные подписи, видимый фокус клавиатуры, текстовые состояния, ограниченные таблицы и компоновку для узкого экрана. Загрузка, пустой результат, отсутствие данных, запрет, потеря связи, устаревание и ошибка различаются. Автоматические браузерные проверки, ручная проверка доступности и приёмка установленного сервиса - отдельные этапы. Документ задаёт контракт до реализации и не разрешает открывать порт или менять рабочий сервис.

## Изолированные проверки

[Браузерный набор](../../scripts/browser/check.mjs) использует настоящий локальный mTLS-сервис с одноразовыми удостоверениями. Двадцать восемь браузерных сценариев проверяют исходный возраст отчета, неизвестное место, ограниченные таблицы, фокус клавиатуры, проверки доступности на двух языках, ширину 320 пикселей и текст 200%, смену области, потерю связи, запрет, пустое состояние, разделение ролей и отказ хранилища до отправки изменения. Ответ теряется после действительного приема команды или конфигурации; после перезагрузки страницы сравниваются исходные байты запроса и идентификаторы. Конкурирующая публикация подписанной политики отклоняет устаревший вариант из браузера.

Версии и хеши Playwright и axe закреплены в [lock-файле тестов](../../scripts/browser/package-lock.json), образ браузера - по digest в [CI](../../.github/workflows/browser.yml). Это только тестовые зависимости. Статические ресурсы продукта встроены в Go-бинарник. На обоих языках автоматические проверки не нашли нарушений; контраст обрезанных прокруткой ячеек остается предметом ручной проверки. Снимки и программные проверки фокуса/масштаба текста не заявляют полное соответствие WCAG или приемку со скринридером. Сценарий восстановления проверяет точный прием запроса и квитанцию; восстановленные байты проверяются отдельно в доверенном исполнителе.

Открыты разрешение неподтвержденных запросов и жизненный цикл журнала сервиса, полная ручная проверка доступности и приемка установленного сервиса. Отсутствие доказательства по хранилищу не подтверждает наличие облачной копии.

Отказ локального хранилища после удаленного приема сообщает о полученной квитанции; исходный запрос остается сохраненным. Ручной поиск квитанции сохраняет данные повтора после перезагрузки. Локальное удаление касается только завершенной записи отслеживания, не удаленной операции.

Дополнительные проверки охватывают несколько вкладок, настоящий перезапуск Chromium с прежним профилем после потери ответа, перенос старого журнала, отзыв прав, отсутствие Web Locks, повреждение хранилища и защиту завершённых квитанций. [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) обеспечивает взаимное исключение в пределах адреса сервиса; [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) и [событие storage](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event) обеспечивают хранение и обновление других вкладок. Событие хранилища не повторяет изменения автоматически.

Владелец может проверить возможность отказа из строки сохранённой операции. Сервис повторно проверяет хеш исходного запроса и отсутствие опубликованного эффекта при подтверждении. Опубликованный или неизвестный эффект запрещает подтверждение. Решение получает отдельный идентификатор внутри исходной записи, поэтому заполненный журнал из 16 записей не мешает действию. После потери ответа повторяются тот же идентификатор и точные байты; `ABANDONED` означает подтверждённый отказ до публикации, а не отмену уже выполняющейся работы. После этого локальную запись можно убрать.

Версия5 [наблюдений внешних копий](external-copy-reporting.md) передает квитанции чтения S3/WebDAV с исходным возрастом. Неизвестное состояние, отсутствие доказательства и старый формат отчета различаются явно; наблюдения не утверждают текущее здоровье облака.
