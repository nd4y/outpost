# Потеря гостевого ядра и порядок подключения тома

[English](../en/virtual-powerloss.md)

Опциональная VM-проверка отличает потерю всего гостевого ядра и непостоянного состояния ФС от завершения процесса Outpost. Она работает внутри допущенного контейнера с ограниченными ресурсами. Хост не перезагружается; его блочные устройства не подключаются, пакеты в его ОС не устанавливаются, сети у гостя нет.

## Входные данные и допуск

Соберите helper в разрешённом окружении сборки:

```sh
CGO_ENABLED=0 go test -c -o /approved-output/worker-vm.test ./internal/worker
```

Обычные тесты пропускают `TestVMKernelFixture`. Для исполнения нужны явный флаг гостевого окружения, root внутри гостя и точный аргумент ядра `outpost_vm_fixture=1`. Внешний контроллер остаётся непривилегированным: без capabilities, с no-new-privileges, seccomp, корнем только для чтения, только loopback, без KVM и с ограничениями cgroup: максимум один CPU, 768 МиБ, без swap, 128 PID.

Подготовьте QEMU, ядро Linux и соответствующие модули virtio/ext4 в порядке зависимостей, статический BusyBox, утилиты ФС и независимо выбранные `outpost`/`outpost-kit`. До исполнения зафиксируйте происхождение, версии и хеши. Это зависимости теста, а не распространяемые продуктом бинарники. Не копируйте initramfs или конфигурацию хоста: там могут быть учётные данные.

Запускайте только внутри допущенного контейнера:

```sh
python3 scripts/check-vm-powerloss.py --config PRIVATE_CONFIG
```

Локальный JSON владельца содержит `schemaVersion: 1`; новый абсолютный `workspace`; шесть элементов `inputs` с именами `qemu`, `kernel`, `helper`, `busybox`, `outpost`, `outpost-kit` и полями `path`/`sha256`; упорядоченные `modules` с теми же полями; `bios`/`biosSHA256`, `qemuData`, `libraryPath`, `mke2fs`, `debugfs`; сведения об исходниках и независимом выборе CLI для отчёта. Эти данные не передаются общим заданиям.

Контроллер создаёт один новый обычный raw-файл на 2 ГиБ и форматирует только его. Существующий результат отвергается. Первичный допуск требует 20 процентов свободного места и запаса под диск и временные файлы. Устройства, существующие образы и рабочие backup-датасеты не могут стать целью форматирования. Лимиты ресурсов, логов и времени фаз сохраняются.

## Авария и восстановление

Четыре зашифрованные фикстуры сохраняют по две версии на 2 МиБ, Unicode-пути, режим доступа и hardlink. Исходный открытый файл и кэши источника удаляются до серии отказов. Приёмнику переданы полномочия проверки поколений; для удаления используется отдельное подписанное разрешение maintenance.

Контроллер завершает только собственный QEMU в точках `object-durable`, `before-complete`, `state-durable`, `retirement-durable`. Следующая загрузка использует ту же виртуальную ФС. Файл, записанный без fsync после границы, должен исчезнуть: это подтверждает потерю непостоянного состояния гостя. Незавершённый приём сохраняет прежнее полное поколение; подтверждённая публикация переживает аварию. Maintenance продолжает записанную операцию, сохраняя последнее полное поколение и отдельно экспортированный старый файловый комплект.

Выбранные самостоятельные CLI восстанавливают обе версии. Все байты проверяются по заранее сохранённому SHA256, вместе с режимом, Unicode-путём и идентичностью hardlink. Процесс приёмника уже завершён до использования материала восстановления.

Ещё пять загрузок проверяют отсутствие диска, неверную ФС, диск только для чтения, отложенное монтирование с последующей инициализацией и позднюю загрузку с правильным томом. Настоящий CLI обязан вернуть `VOLUME_UNAVAILABLE` с кодом 5 при недоступном хранилище и не создать запасное состояние. Отдельная проверка volume-guard связывает отказ с допуском тома. Правильное хранилище сохраняет допущенную идентичность.

## Граница результата

Гость использует ext4 с периодическим commit раз в 60 секунд; явный fsync по-прежнему обязателен. QEMU работает с обычным raw-файлом и `cache=directsync`. [Руководство запуска QEMU](https://www.qemu.org/docs/master/system/invocation.html) описывает параметры ускорения и кэша; [справочник блочных драйверов](https://www.qemu.org/docs/master/system/qemu-block-drivers.html) - raw-образы. Хост продолжает работать. Это не приёмка кэша физического контроллера, отключения питания хоста, настоящей разблокировки диска или другого аппаратного домена отказа.

Доказательства должны указывать дерево/helper, хеш контроллера, ревизию CLI, ядро/модули, пакеты инструментов, наблюдения ресурсов, логи отдельных фаз и неуспешные контроли. Пропущенный Go-тест, успешная загрузка или наличие символа не означают приёмку. Ограниченный набор не заменяет 100 ГиБ, асимметричный ingress, облачную производительность и реальные профили.

[Зафиксированный ограниченный прогон](../vm-powerloss-evidence.json) прошёл все 14 фаз: подготовку, четыре отключения с четырьмя загрузками восстановления и пять загрузок с разным состоянием тома. Пик памяти - 609734656 байт при лимите 768 МиБ, swap и OOM не было. Неудачные проверки наблюдателя сохранены с объяснением причин. Результат подтверждает только описанные выше границы.
