# Приватный агент источника

[English](../en/source-agent.md)

Агент Linux связывает [цикл источника](source-jobs.md) с допущенным [рабочим томом](runtime-volume.md), приватным кешем метаданных и HTTPS-приёмником. Установленный провайдер дерева объявляет согласованность `best-effort`. Он сверяет файловую систему/inode корня, запрещает ссылки и пересечение с рабочим хранилищем; при освобождении представления не удаляет, не размонтирует и не изменяет файлы источника.

Приватный bootstrap `outpost-source-agent-1` содержит `local` (bootstrap2: нода, публичный ключ владельца, том, рабочий каталог и файлы сертификата/ключа/CA), `profile` (непрозрачные ID/происхождение, отбор, пределы, согласованность и копии), `tree` (наблюдение от `source-probe`), `dataKeyFile`, `writerKeyFile`, `authorityFile`, HTTPS `endpoint` и дисковые `limits`. Поле `view` профиля пустое; агент назначает ID операции. Файл ключа подписания использует JSON-поле `privateKey`. Адрес control plane, слушающий порт и облачные реквизиты не являются входами агента источника. Правила источника и ключи расшифровки не входят в общие задания.

Файлы ключей/конфигурации должны быть приватными обычными файлами; ссылки в родителях и конечном компоненте запрещены. Источник и родитель рабочего каталога должны существовать. Инициализация проверяет пересечение до создания рабочего состояния и отказывает для существующего назначения. Прерванная начальная установка требует проверки оператором, а не автоматического сброса. Отсутствие маркера, подмена каталога, изменение привязки bootstrap/ключей и откат часов блокируют допуск.

Текущий исполняемый агент принимает профиль best effort с одной копией. Запрос двух копий, снимка файловой системы или согласованности приложения возвращает `CAPABILITY_UNAVAILABLE`, сохраняя требования политики. Библиотека захвата уже требует две разные проверенные копии; интеграция её аутентифицированного сетевого проверяющего ещё необходима.

```sh
outpost source-probe --store /source/tree --node ORIGIN_ID --output /private/tree.json
outpost source-authority-sign --key /private/owner-key.json \
  --input /private/authority-input.json --output /private/authority.json
outpost source-init --bootstrap /private/source.json
outpost source-next --bootstrap /private/source.json
outpost source-run --bootstrap /private/source.json
outpost source-status --bootstrap /private/source.json
outpost source-checkpoint --bootstrap /private/source.json --output /private/checkpoint.json
```

`source-next` подписывает операцию от сохранённого последнего поколения. Повтор при незавершённой операции возобновляет её; после завершения подготавливаются следующий номер и точный предок. `source-prepare --bootstrap FILE --input SIGNED_INTENT` принимает переданное намерение с той же защитой от подмены. `source-run` выполняет/возобновляет подготовленную операцию и остаётся идемпотентным после завершения; он не создаёт ещё одно поколение и не запускается по расписанию.

Подписанное состояние агента фиксирует операцию до подготовки провайдера. Подписанные результаты файлов и зашифрованный прогресс принятых пакетов переживают перезапуск. После запечатывания источник не открывается повторно. Потеря последнего обновления головы цепочки возобновляет завершённое задание и выгружает проверенную контрольную точку/связь версий. Кеш хранит зашифрованные метаданные/прогресс вместо полной копии содержимого. Квоты и сверка сохраняют непринятые файлы, не удаляя их.

Статус показывает непрозрачные идентичности, этапы и наблюдения копий без имён источника и ключей. SIGINT/SIGTERM сохраняют устойчивый прогресс. Контроль тома отменяет текущие HTTPS-запросы при потере идентичности и завершается вместе с заданием; принудительное прерывание вызова файловой системы, зависшего внутри ядра, не обещается. Контрольная точка записывается в новый приватный файл без перезаписи. Независимому восстановлению также нужны владелец ключей комплекта файла, публичные полномочия поколения и полное зашифрованное содержимое; одна контрольная точка или кеш источника копией не являются.
