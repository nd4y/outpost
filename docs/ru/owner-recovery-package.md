# Комплект восстановления владельца

[English](../en/owner-recovery-package.md)

`outpost-owner-recovery-1` содержит материал и выбранные инструменты для чтения независимо сохранённого шифротекста. В него входят владелец file kit только для чтения, публичные ключи проверки поколений, поддерживаемые форматы, последняя сохранённая завершённая контрольная точка источника при её наличии, выбранный manifest дистрибутива, архивы Linux amd64/arm64 и инструкции на двух языках. Резервные данные, доступы к облаку, учётная запись control plane и закрытые ключи подписи не включаются. Экспорт не меняет и не отзывает ключи.

Комплект содержит **открытые секреты расшифрования**. Храните его в приватном хранилище владельца отдельно от источников и реплик. Он не предназначен для недоверенных нод. Сохраните SHA-256 комплекта отдельно в доверенном месте: хеш, вычисленный из неизвестного файла, не является независимым основанием доверия. Приватные права и непересекающиеся каталоги не доказывают независимость оборудования, сохранность носителя или наличие отключённой копии.

## Экспорт из источника

Подготовьте приватный профиль `outpost-source-recovery-export-1` со следующими полями:

| Поле                 | Значение                                                                               |
| -------------------- | -------------------------------------------------------------------------------------- |
| `format`             | `outpost-source-recovery-export-1`                                                     |
| `volume`             | Отдельно зарегистрированная привязка тома владельца; scope совпадает с нодой источника |
| `directory`          | Существующий абсолютный приватный каталог внутри этого тома                            |
| `toolsDirectory`     | Существующий каталог дистрибутива вне выходного каталога                               |
| `toolManifestSHA256` | Независимо выбранный SHA-256 файла `manifest.json` этого дистрибутива                  |

Корень тома владельца не должен пересекаться ни с деревом источника, ни со всем корнем рабочего тома агента. Результат должен быть новым файлом непосредственно в `directory`. Символические ссылки в компонентах пути запрещены. Профиль, выходной каталог и комплект приватны: каталоги имеют режим 0700, файлы комплекта - 0600. Ревизия выбранных инструментов должна совпадать со встроенной ревизией экспортирующего CLI. Формат дистрибутива, набор архитектур, хеши архивов и их членов, заголовки статического Linux ELF и точный состав файлов проверяются до записи секретов восстановления.

```sh
outpost source-recovery-export --bootstrap /private/source.json \
  --input /private/owner-export.json --output /owner/private/recovery-001.tar
```

Сохраните успешный JSON-результат, включая SHA-256 всего комплекта, отдельно. Источник копирует материал расшифрования, публичное доверие и последнюю завершённую контрольную точку под блокировкой исполнения, затем освобождает её до копирования инструментов. Уже ожидающий следующий захват не заменяет завершённую точку. Допуск тома и приватных путей проверяется ещё раз перед публикацией. Экспорт не изменяет источник, политику, ключи или контрольную точку.

Сейчас операция требует доступности допущенного рабочего каталога агента и зарегистрированной идентичности дерева источника. Подготовьте и сохраните комплекты до потери этого состояния. После экспорта проверка, распаковка и явное автономное восстановление не требуют тома источника, учётной записи или журнала.

## Автономная проверка и восстановление

Используйте ранее доверенный совместимый исполняемый файл и отдельно сохранённый хеш комплекта:

```sh
outpost recovery-package-inspect --input /owner/private/recovery-001.tar \
  --sha256 EXPECTED_PACKAGE_SHA256
outpost recovery-package-extract --input /owner/private/recovery-001.tar \
  --sha256 EXPECTED_PACKAGE_SHA256 --output /owner/private/unpacked-001
```

Весь файл проверяется до разбора секретов или создания кандидата распаковки. Распаковка проверяет байты повторно и публикует новый приватный каталог только после синхронизации всех файлов и каталогов. Вложенные архивы инструментов не распаковываются и не запускаются автоматически. Выберите архив своей архитектуры и распакуйте его в другой приватный каталог инструментов. Если совместимой программы ещё нет, сначала проверьте весь комплект отдельно доверенной утилитой SHA-256, затем используйте системный архиватор для подготовки инструментов в новом приватном каталоге. Нельзя доверять неизвестному комплекту только на основании хешей внутри него.

Для полной материализованной реплики используйте извлечённые ключи, явно выбранное сохранённое поколение и новый выходной каталог:

```sh
/owner/tools/outpost restore-replica \
  --key /owner/private/unpacked-001/recovery-owner.json \
  --trust /owner/private/unpacked-001/trust.json \
  --store /ciphertext/replica --generation GENERATION_ID --output /restore/new
```

Для отдельно экспортированного комплекта файла используйте `restore-kit --key ... --store ... --version VERSION_ID --output ...`. Проверяйте восстановление выбранного файла и полной реплики отдельно. Оба сценария используют материал восстановления только для чтения.

## Подготовить новую эпоху ключей

На автономном хосте владельца допустите приватный том с областью, равной SHA-256 исходных байтов публичного ключа полномочий Ed25519. Создайте на нём приватный родительский каталог для результата. Приватный запрос `outpost-owner-epoch-request-1` содержит привязку `volume`, абсолютный путь родителя `directory`, непрозрачный `operationId` и причину `reason`. Для первой эпохи укажите `initial`. Для `scheduled-rotation`, `key-compromise` или `placement-change` передайте `prior.path` и независимо сохранённый `prior.sha256` предыдущего комплекта с проверенной контрольной точкой.

Запустите `owner-epoch-create --input PRIVATE_REQUEST --key OWNER_AUTHORITY --output NEW_PRIVATE_DIRECTORY`. Файл полномочий содержит `privateKey`. Команда публикует отдельный домен и репозиторий, разные ключи данных, записи и обслуживания, `trust.json` и подписанный владельцем `preparation.json`. Квитанция связывает прежнюю контрольную точку и её возраст, операцию и исполнителя. Права приватных файлов - 0600. Ключ обслуживания храните у владельца. Каждому допущенному компоненту выдавайте только нужные ключи.

Если ответ потерян, проверьте готовый результат командой `owner-epoch-inspect --input PREPARATION_RECEIPT --trust OWNER_PUBLIC_KEY` и сопоставьте операцию. Файл доверия содержит независимо сохранённый `publicKey`. После квитанции `PREPARED` отдельно применяют политику и допускают источник. Храните прежний комплект и его шифротекст весь срок хранения старой эпохи. Перед выводом её материала из использования восстановите сохранённые версии обеих эпох соответствующими комплектами и подтвердите блокировку старых полномочий записи.

## Остановить запись из прежнего источника

После подтверждения полной контрольной точки новой эпохи и независимого восстановления владелец старого источника может подписать точный локальный запрет. Запустите `outpost source-writer-fence-sign --key OLD_SOURCE_OWNER_KEY --input PRIVATE_REQUEST --output NEW_SIGNED_FENCE`. Запрос `outpost-source-writer-fence-1` содержит `operation`, `source`, `profile`, SHA-256 точной старой точки в `previousCheckpoint`, квитанцию `preparation` и `successorCheckpoint` в base64, хеш доказательства независимого восстановления `restoreEvidence`, `notBefore` и `expiresUnix`. Если подготовку подписала другая допущенная сторона, закрепите её публичный ключ в `preparationAuthority`. Доказательство восстановления указывает владелец. Старый источник проверяет подписи квитанции и новой точки, а также заданное минимальное число копий.

Примените запрет командой `outpost source-writer-fence --bootstrap OLD_SOURCE_FILE --input SIGNED_FENCE`. Источник проверяет точную полную версию и завершённую уборку приёмных слотов, затем устойчиво записывает запрет под блокировкой захвата. `source-status` показывает исходное время и хеши доказательств. Захват, выполнение расписания и обновление полномочий возвращают `WRITER_FENCED`. Точный повтор возвращает сохранённый результат. Исторические контрольные точки и экспорты доступны. У запрета нет локального отката, для журнала нужен совместимый исполняемый файл. Отзыв старых доступов на держателях и применение новой политики выполняются отдельно. Старый комплект и его шифротекст хранятся весь согласованный срок.

Ограниченный тест процедуры владельца связывает фактическую квитанцию подготовки через CLI, подписанную точку новой эпохи и восстановленные комплектным инструментом байты с этим запретом. После повторного открытия старый источник отклоняет следующий захват и сохраняет исходную контрольную точку. Затем обе эпохи снова восстанавливаются своими комплектами при выключенных источниках и приёмниках. Ограниченный сценарий отзыва доступов на держателях и устойчивого запрета отката эпохи описан в квитанции ниже; вывод старого ключевого материала и приёмка жизненного цикла на полном объёме остаются отдельными этапами.

`checkpoint.json` сохраняет исходную подписанную точку и время проверки. Время экспорта не продлевает сведения об исправности копии и не доказывает отсутствие более новой версии. Отсутствующая или старая точка ограничивает знание актуальности, но не мешает расшифровать явно выбранную корректную версию с подходящими ключами. Результат содержит только непрозрачные идентификаторы, версии, размеры, хеши и исходное время точки.

## Прерывания и пределы

Существующие комплекты и результаты распаковки не перезаписываются. После прерванной или отклонённой записи остаётся приватный кандидат `.partial-recovery-...`. Для каждого точного выходного имени допускается не более четырёх кандидатов под прерываемой блокировкой каталога; просмотр родительского каталога ограничен 4096 элементами. Неуспешные кандидаты сохраняются для проверки владельцем, не используются повторно и не удаляются автоматически. Размер комплекта ограничен 256 МиБ, каждого сжатого архива инструментов - 64 МиБ, его распакованных файлов - 128 МиБ, manifest - 2 МиБ. Допускаются только фиксированные имена, обычные файлы и объявленные архитектуры. Это пределы операции, а не общая политика хранения тома владельца или доказательство достаточного физического места.

После неопределённого ответа конечный результат уже может существовать. Проверяйте его только при наличии независимо известного ожидаемого хеша. Если квитанция экспорта потеряна, сохраните неопределённый результат и выполните экспорт под другим новым именем из всё ещё доверенного материала источника; отдельно сохраните новый хеш. Нельзя заменять прежний комплект или создавать доверие вычислением хеша неопределённого файла.

Короткие проверки на HDD покрывают приватный допуск, подмену данных, некорректные архивы, проверку статических утилит, конкуренцию, потерю ответа, исходный возраст точки, потерю тома владельца, принудительное завершение процессов и независимое восстановление старых и новых файлов и полных реплик выбранной упакованной программой. Записи фактических запусков и приёмка текущих инструментов отделены от ссылок на функции тестов. Восстановление полного масштаба, физическая потеря носителя, жизненный цикл ключей и полная приёмка продукта остаются открытыми в [статусе продукта](../product-status.json).

[Квитанция эпох держателя](../g2-history-evidence.json) дополняет процедуру CLI владельца: настоящий TLS-обмен воркеров, устойчивый запрет отката эпохи и независимое восстановление обеих сохранённых эпох прошли на изолированном HDD-стенде. Это не разрешение и не реализация уничтожения прежних ключей.
