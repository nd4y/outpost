# Профиль приёмки инфраструктуры

[English](../en/infrastructure-profile.md)

ТЗ задаёт поведение продукта. Приватный профиль владельца связывает его с конкретными источниками, нодами и провайдерами до пилота. Адреса, идентичности машин, аккаунты, имена наборов, наблюдения и runbooks хранятся вне публичного Git. Статические документы профиля можно синхронизировать; изменяемые runtime-базы не используют неподдерживаемую файловую синхронизацию.

У профиля есть версия, владелец, дата проверки, версия ТЗ и статус: proposed, measured или accepted. Каждое значение помечено как наблюдаемое, предлагаемое или неизвестное. Наблюдение содержит время и доказательство; неизвестное - ответственного, этап и способ проверки. Неизвестная обязательная предпосылка блокирует соответствующую операцию. Профиль не разрешает deployment.

Наблюдение возможности отличается от проверки её действия. Поле конфигурации Docker не доказывает применения лимита. Каталог состояния на том же диске не является ещё одной репликой. Рестарт контейнера не заменяет холодную загрузку хоста. Файловый профиль не подразумевает штатное восстановление пакетов NAS.

Для каждого блокирующего условия записывается конкретный способ его закрытия. Владелец выбирает назначение по измеренной ёмкости; нельзя предполагать сжатие или снижать контрольный резерв без фиксации нового профиля. Например, worker с малой памятью и source на cgroup v1 могут требовать иных ограничений, чем тестовый хост cgroup v2. Это классы, а не заявление измеренной поддержки продукта.

До масштабной приёмки выделяется место для несжимаемого сценария 100 GiB, истории, автономных комплектов и временных данных. Малые fixtures доказывают только заявленное поведение. G1 определяет допустимую стоимость и дополнительный расход до выбора формата. Покрытие legacy сохраняется до приёмки согласованного восстановления замены.
