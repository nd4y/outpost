# Жизненный цикл задания источника

[English](../en/source-jobs.md)

Контракт связывает приватный планировщик источника, потоковые комплекты файлов и аутентифицированный приём. Это контракт разработки; карта готовности отдельно отражает реализацию и приёмку.

Текущий координатор сохраняет приватный план, подписанные результаты файлов и подписанную контрольную точку восстановления. Короткие тесты покрывают синтетический провайдер, настоящую вторую материализованную копию, повреждение контрольной точки и четыре реальные остановки SIGKILL. [Агент источника](source-agent.md) связывает провайдер дерева best effort, допуск тома, квоты, HTTPS-приёмник и цепочку следующих поколений. Его тесты независимо восстанавливают два поколения после потери источника. Исполняемый агент получает аутентифицированные подтверждения второй копии через приёмник-сборщик. [Устойчивое расписание источника](source-scheduling.md) выполняет ограниченные захваты и продолжает незавершённые намерения. [Провайдер подготовленного экспорта](prepared-exports.md) допускает подписанные нативные экспорты приложений; получение снимков файловой системы и рабочий допуск конкретных приложений остаются отдельной работой.

До передачи содержимого операция фиксирует приватный профиль, идентичность представления провайдера, полный план отбора, идентичности файлов, предыдущие версии и подписанное намерение приёма. Пути, правила отбора и ключи данных остаются на доверенном источнике. Каждый файл классифицируется со всеми псевдонимами до упаковки. Изменение источника делает план best effort недействительным; чтение каталога не называется снимком приложения.

При наличии надёжного времени создания идентичность файла вычисляется с ключом по домену, происхождению провайдера, устройству/inode и времени создания. Переименование может сохранять связь версий без записи xattr в источник. При отсутствии времени создания используется новая случайная идентичность без обещания повторного использования. Провайдер снимков должен задавать стабильное происхождение и проверять семантику inode/устройства; результат на локальной файловой системе не доказывает непрерывность между произвольными снимками или клонами.

Устойчивый порядок: `PLANNED`, `CAPTURING`, `SEALED`, `WAITING_COPIES`, `CHECKPOINTED`, `RELEASING`, `RELEASED`, `ACKNOWLEDGING`, `COMPLETE`. Повтор сохраняет ту же операцию и подписанное намерение. Каждая принятая версия файла получает локальную контрольную точку; прерванный большой файл использует зашифрованный журнал принятых пакетов. Контрольные точки не обещают продолжение чтения источника с прерванного байта.

Публикация проверяет точный подписанный каталог через приёмник. Заданный порог копий считает разные разрешённые полные копии этого каталога, сохраняя тип проверки и исходное время наблюдения. Попытка отправки или запись очереди копией не является. Одна копия у приёмника и политика двух копий имеют разные условия освобождения. Отсутствующие необязательные ноды или ноды с длительным отключением не продлевают удержание представления источника после достижения необходимого порога.

Источник устойчиво сохраняет подтверждение и контрольную точку восстановления до освобождения провайдера. Получение и освобождение представления идемпотентны по идентичности операции и представления. Неопределённый результат освобождения повторяется как освобождение, без повторного получения или чтения источника. Только после подтверждённого освобождения источник разрешает очистку приёмника. Потерянный ответ повторяется с тем же сохранённым подтверждением. Очистка прогресса удаляет только приватные метаданные этой операции и не удаляет поколения копий.

Провайдеры являются установленными реализациями с явными проверками согласованности и возможностей, а не удалённым текстом shell-команд. Дерево best effort, допущенный снимок только для чтения и экспорт приложения имеют разные декларации и процедуры восстановления. Отсутствие обязательных возможностей запрещает запуск. Рабочий кеш, метаданные, прогресс и изменения под удерживаемым снимком имеют отдельные пределы учёта; их исчерпание сохраняет предыдущие полные версии. Приёмка нативного провайдера и инфраструктуры отделена от синтетических тестов заданий.
