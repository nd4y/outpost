# Допуск тома рабочего состояния

[English](../en/runtime-volume.md)

Устанавливаемый воркер должен привязать приватный рабочий каталог к явно допущенной локальной файловой системе до инициализации. Отсутствующий, заменённый, заблокированный или доступный только для чтения том не должен приводить к созданию нового состояния в нижележащем каталоге. Допуск является отдельной локальной операцией владельца; удалённая конфигурация не выбирает новый том.

Локальная привязка содержит разрешённый абсолютный корень тома, тип и идентификатор файловой системы, inode корня и хеш приватного случайного файла-маркера. Они определяют наблюдавшуюся файловую систему/каталог; идентификатор файловой системы не называется универсально доступным UUID. До записи маркера допуск сравнивает переданное наблюдение со свежей проверкой. Компоненты пути открываются без перехода по символьным ссылкам. Рабочий каталог должен быть строгим потомком без символьных ссылок и вложенных монтирований среди существующих компонентов. Рабочая файловая система должна поддерживать принятую локальную модель блокировок/fsync; первый профиль разрешает только ext4, Btrfs и XFS.

Bootstrap, каждый цикл/запрос работающего воркера и допуск записи повторно проверяют привязку. Идентичность монтирования является текущим наблюдением, а не постоянным значением между перезагрузками. Ошибка останавливает новую работу и сохраняет накопленные данные. Удаление маркера или изменение привязки не является командой очистки либо миграции. Восстановление доступной материализованной копии остаётся отдельным процессом с чтением входных данных.

Формат `outpost-bootstrap-2` требует привязку `volume`, область которой совпадает с идентичностью ноды, и ненулевую эпоху допуска. Состояние, кеш конфигурации, учёт места, копии, журналы передачи, сессии приёма, очереди выгрузки и явная миграция индекса открываются относительно сохранённого дескриптора рабочего каталога. Подмена пути не перенаправляет их запись. Контролируемый монитор отменяет активную работу при потере идентичности; допуск проверяет привязку перед записью и повторно до сообщения об успехе. Это не делает зависший системный вызов I/O отменяемым.

Локальное зачисление использует `volume-probe --store DIRECTORY --output PRIVATE_PROBE_FILE`, затем `volume-enroll --store DIRECTORY --input PRIVATE_PROBE_FILE --node NODE_ID --epoch 1 --output NEW_BINDING_FILE`. Оба файла должны оставаться приватными. Первичное зачисление требует пустой выбранный каталог. Наличие состояния без маркера запрещает зачисление. Повтор с теми же корректными областью и эпохой идемпотентен; их изменение отклоняется. Зачисление не создаёт снимок источника и не меняет монтирование, разблокировку либо сеть хоста.

Старый bootstrap без привязки отклоняется. Поддерживаемая миграция уже привязанного тома требует отдельной процедуры смены идентичности с блокировкой старой; удаление маркера или редактирование JSON такой процедурой не является. Инициализация устойчиво создаёт принадлежащие системе каталоги и синхронизирует их родителей. Неизвестная обязательная идентичность или неподдерживаемая файловая система запрещает работу. Синтетические тесты проверяют отказ и отсутствие записи в подменный каталог; холодный старт, реальный порядок разблокировки и потеря тома во время I/O требуют отдельной инфраструктурной приёмки владельца.
