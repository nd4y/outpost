# Подключение стандарта разработки

[English](../en/development-standard.md)

Outpost подключает Development Standard **0.4.0** через автономный публичный пакет с контрольными суммами. [Lock](../../.standards/lock.json), [английские правила](../../.standards/rules.en.md) и [русские правила](../../.standards/rules.ru.md) работают без доступа к приватному управляющему репозиторию. Включён только разрешённый состав; приватный реестр и эксплуатационный профиль не публикуются.

Коммит источника пакета (SHA-1): `75833a42311832d1de665d0e441adac2b5b701d2`.

Проект является экспериментом со статусом внедрения **adopting**. Проверки репозитория можно принять отдельно от реализации, runtime и профильных испытаний. См. [аудит 45 правил](standard-review.md).

## Профили и исключения

Применяются web, cli, library, service, network, integration, infra, monitoring, data и docs: UI/CLI, потребитель API, права контейнера, частичная связность, провайдеры, установка/diff, телеметрия и backup/restore. Mobile, ML и firmware вне объёма. Утверждённых исключений нет.

Исключение должно содержать правило, область, причину/риск, владельца, компенсацию и дату пересмотра. MUST блокирует соответствующий этап. Нельзя ослаблять strict docs-policy и обязательные проверки для получения PASS.

## Подготовка и команды

```sh
npm ci --prefix .standards --ignore-scripts --no-audit --no-fund
node .standards/install-gitleaks.mjs
node .standards/install-hooks.mjs
node .standards/check.mjs structure
node scripts/check-docs.mjs
node scripts/check-format.mjs
node scripts/check-standard-adoption.mjs
```

Инструменты: локально Node.js 22+, в CI Node.js 24.18.0, Prettier 3.9.10 и проверенный по сумме Gitleaks 8.30.1. Нужны Git, npm, tar и POSIX shell для hook. Прототип M0 использует Go 1.27.3: штатные gofmt, go test и go vet запускаются в prototype workflow. Синтетическая интеграционная фикстура работает без сети и приватных credentials; см. [команды G1 и ограничения](g1-prototype.md). Производственный worker ещё не реализован.

Форматирование: `node scripts/check-format.mjs --write`, затем просмотр diff и staging только нужных файлов. Pre-commit запускает `node .standards/check.mjs staged` по содержимому индекса, сохраняет частичный staging и вызывает прежний hook первым. Не правьте vendored toolkit ради форматирования проекта.

После staging можно запустить его проверку отдельно. Проверка полной истории перед публикацией в POSIX:

```sh
.standards/bin/gitleaks git . --log-opts=--all --redact --no-banner --config .standards/gitleaks.toml
```

На Windows используйте те же аргументы с `.standards/bin/gitleaks.exe`. Недоступный сканер блокирует публикацию. Тест подключения создаёт одноразовый локальный Git: принимает корректную правку и отклоняет плохое форматирование, отсутствие языка, пробельные изменения, удаление документации, синтетический секрет и недоступный сканер. История проекта не меняется, внешних обращений нет.

## CI и merge

Отдельный workflow repository-standard проверяет полный diff PR, пакет, содержательную двуязычную документацию, форматирование и секреты. Дополнительно проверяется полная история, включая первый корневой коммит, который мог бы не попасть в обычный диапазон. Workflow документации проверяет языковые пары, ID, ссылки, полное форматирование и семь сценариев пакета.

Оба используют SHA actions, read-only permissions и hosted runners. PR из форка не требует секретов и внутренней сети. Обязательные статусы должны относиться к точному head. Защита main включается после реального успешного запуска и проверяется отдельно от наличия YAML.

После начальной публикации используются ветки/PR; merge выполняет владелец. Обход защиты и скрытое ослабление проверок запрещены. Исходный policy не предсказывает будущий CI: результат смотрится для точного commit в Actions. Release/runtime остаются NOT_VERIFIED до приёмки.

## Доказательства обновления и откат

Фиксируйте commit/digest, среду, команды, время, результат и непроверенные пути. [requirements.json](../requirements.json) содержит 53 требования и 35 запланированных сценариев. [Трассировка G1](g1-acceptance.md) связывает REQ-09/10/11 с реальными проверками файловых комплектов и измеренными пределами ресурсов. Проверка контролирует структуру, а ревью - смысл двух языков. Runtime принимается на G1-G3 и M1-M5.

Обновление пакета выполняется версионированным PR с проверкой сумм и негативных сценариев. Для локального отката hook восстановите hooksPath из repository-standard-hook.json в локальном каталоге Git; прежний hook сохранён. Удаление подключения требует проверяемого PR без потери проверок продукта. Инфраструктурные правила и профиль сборок остаются приватными.
